# 御端（YuDuan）中枢 Windows 服务器部署操作手册（v0.4.33）

> 适用中枢版本：**v0.4.33**（Windows 部署脚本 `register-task.ps1` v2）。  
> 本文以发布包 `yuduan-hub_v0.4.33_windows_amd64` 内的 `register-task.ps1` / `deploy.bat` / `env.example` 为准，逐行核对编写。  
> **本文取代**旧版 `御端中枢_手动部署教程_Windows.docx` 与 `御端中枢v0.4.32_部署操作指引_新参数版`——在原 13 个部署开关基础上，新增 v0.4.33 的 **§9.2 设备证明** 两个开关（`-AttestRequire` / `-AttestTrustedMeasurements`）与「开关可达性 + 可观测」收口。  
> 所有命令均在【管理员 PowerShell、`cd` 到中枢安装目录】下执行。中枢安装目录 = 解压后与 `yuduan-hub.exe`、`register-task.ps1` 同级的目录（如 `D:\yuduan-hub`）。**中枢唯一配置源是该目录下的 `hub.env`**，所有开关最终都落到 `hub.env` 的 `KEY=VALUE` 行。

## 一、参数总览（15 个开关 / 值）

下表为 `register-task.ps1` 的完整参数。**加粗**为 v0.4.27~v0.4.33 新引入；「引入版本」取自脚本注释。

| 参数 | 类型/默认 | 引入 | 一句话作用 |
|---|---|---|---|
| `-Remove` | 开关 | 基础 | 只卸载服务与防火墙规则（保留 `hub.env` 与数据目录） |
| `-ResetConfig` | 开关 | 基础 | 删除既有 `hub.env` 并重新生成全套随机密钥（HMAC/PEPPER/SIGN_SEED）——所有副端必须重新 claim |
| `-DbDsn` | 字符串 `""` | v0.4.21 | 直接指定 PostgreSQL DSN，跳过交互询问，写入 `YUDUAN_DB_DSN` |
| `-NonInteractive` | 开关 | v0.4.23 | 绝不阻塞等待任何输入；能自动则自动，不能自动则黄色 WARN 降级后继续（`deploy.bat` 恒传此开关） |
| `-TaskName` | 字符串 `YuDuanHub` | 基础 | 计划任务名（开机自启、SYSTEM 身份） |
| `-AgentDir` | 字符串 | 基础 | 同机副端 deploy 目录（含 `install-agent.ps1`）——提供则自动把 HMAC 同步给副端，零手填 |
| `-Public` | 开关 | v0.4.27 | 公网部署模式：在 LAN 部署之上额外做证书准备 + 写公网 env + 放行 8443 |
| `-Domain` | 字符串 `""` | v0.4.27 | 公网 FQDN（`-Public` 时必填） |
| `-Email` | 字符串 `""` | v0.4.27 | 证书联系人邮箱（`-Public` 时必填） |
| `-CertMode` | 字符串 `self` | v0.4.27 | 证书模式：`acme`=自动签发受信任证书 \| `self`=私有 CA 自签（`-Public` 时必填且只能是二者之一） |
| `-DiscoveryPort` | 整数 `18242` | v0.4.29 | UDP 自动发现端口，写入 `YUDUAN_DISCOVERY_PORT`，防火墙按此放行 UDP；三端须一致；合法 1..65535 |
| `-Staging` | 开关 | v0.4.27 | ACME 预发验证：追加 `--staging` 走 Let's Encrypt 测试环境 |
| `-Memory` | 开关 | v0.4.30 | 显式允许内存模式（默认拒绝静默内存模式，防丢数据）；仅供测试 |
| **`-AttestRequire`** | **开关** | **v0.4.33** | **设备证明强制校验：开启时副端必须附带有效证明（Ed25519 验签 + 度量白名单命中）才能注册；关闭（默认）时对旧副端逐字节兼容放行** |
| **`-AttestTrustedMeasurements`** | **字符串 `""`** | **v0.4.33** | **可信度量白名单——逗号分隔的可执行文件 SHA-256 hex（小写）；非空时副端上报的 `measurement` 必须命中其一，否则拒绝；留空则仅验签不约束度量** |

脚本内置校验：`-Public` 时若缺 `-Domain`/`-Email` 或 `-CertMode` 不是 `acme`/`self` 立即 `Write-Error` 中止；`-DiscoveryPort` 不在 1..65535 立即中止；**`-AttestTrustedMeasurements` 每个条目必须是 64 位 hex，否则立即中止**（v0.4.33 新增）。

## 二、三种部署模式与选型

按用途选一条路径即可；命令均在管理员 PowerShell、中枢安装目录下执行。

| 模式 | 适用场景 | 核心命令（register-task.ps1） | 持久化 | 对外可达 |
|---|---|---|---|---|
| **A 测试 / 内存** | 功能验证、临时演示、单机自测 | `-ResetConfig -Memory -NonInteractive` | 无（重启丢数据、admin 口令复位） | 仅本机 / 局域网 8080 |
| **B 持久化投产（内网）** | 正式内网部署，需保数据、可备份 / 集群 | `-DbDsn "postgres://yuduan:CHANGE-ME@127.0.0.1:5432/yuduan?sslmode=disable"` | PostgreSQL（`YUDUAN_DB_DSN`） | 局域网 8080 / 8443 |
| **C 公网投产** | 需要 HTTPS/WSS 对外、证书受信任 | `-Public -Domain hub.example.com -Email ops@example.com -CertMode acme [-Staging]` | PostgreSQL（须已配或自动就绪） | https://域名:8443 |

模式 C 用私有 CA 而非公网受信任证书时，把 `-CertMode acme` 换成 `-CertMode self`（self 走 `prepare-public-cert.ps1` / `yuduan-ca.exe` 自签，副端需带外预置 `ca.pem` 或 PIN）。

**模式 B 启用设备证明（高安全内网 / 合规场景）时追加开关：**

```powershell
# 仅强制验签（不约束度量）：
.\register-task.ps1 -DbDsn "postgres://yuduan:CHANGE-ME@127.0.0.1:5432/yuduan?sslmode=disable" -AttestRequire

# 强制验签 + 度量白名单（逗号分隔 64hex）：
.\register-task.ps1 -DbDsn "postgres://yuduan:CHANGE-ME@127.0.0.1:5432/yuduan?sslmode=disable" `
  -AttestRequire -AttestTrustedMeasurements <sha256>,<sha256>
```

> ⚠️ **全网强制 `YUDUAN_ATTEST_REQUIRE=1` 要求全网副端 ≥ v0.4.31**（含 §9.2 契约基座，能生产 `pubkey/attest_sig/measurement`）。混网旧副端在强制模式下会被拒绝——须先完成全网副端升级再开灰度。

## 三、逐参数详解

### 3.1 `-Memory` —— 显式内存模式（v0.4.30，仅测试）
从 v0.4.30 起，部署脚本默认【拒绝静默内存模式】。当既没有 `-DbDsn`、hub.env 也没有 `YUDUAN_DB_DSN`、且 PG 自动就绪也失败时：
- 交互模式（不带 `-NonInteractive`）：粘贴 DSN → 持久化；输入 `memory` → 强制内存模式；直接回车 → 部署中止（exit 1）。
- 一键/非交互（`deploy.bat` 恒带 `-NonInteractive`）：直接 `[ERROR] 未配置 PostgreSQL 且未能自动就绪：一键部署中止`（exit 1）。

因此 `-Memory` 是唯一的“逃生舱”：加上它才打印黄色 WARN「显式 `-Memory`：中枢将以内存模式运行（重启丢数据，仅供测试）」并继续。内存模式后果：进程重启丢设备/台账/审计，admin 口令复位为默认，备份与多中枢不可用。**投产严禁依赖内存模式。**

### 3.2 `-DbDsn` —— 直接给定持久化（v0.4.21）
值原样写入 `hub.env` 的 `YUDUAN_DB_DSN`（覆盖既有值）。中枢启动时自动建表（幂等）；连不上会启动报错退出，不会静默丢数据。

| 项 | 要点 |
|---|---|
| URL 格式（推荐） | `postgres://yuduan:CHANGE-ME@127.0.0.1:5432/yuduan?sslmode=disable` |
| libpq 键值格式 | `host=127.0.0.1 port=5432 user=yuduan dbname=yuduan password=CHANGE-ME` |
| 口令纪律 | 纯 ASCII；避开 cmd 元字符 `% ! ^`；URL 里特殊字符须百分号编码（`@ : /` 等）。内置 pg 客户端明文连接，`sslmode` 被忽略，靠内网+防火墙白名单保护 |
| 前置条件 | 目标 PG 里已建 `yuduan` 角色与库（`CREATE USER yuduan ...; CREATE DATABASE yuduan OWNER yuduan;`） |

不给 `-DbDsn` 时脚本先尝试「自动就绪」：检出本机 PG 直接复用 → 端口空闲则用捆绑/下载的便携包装成 `yuduan-pg` 服务并自动建号建库（随机 24 位 hex 口令，不回显）。任一步需人工输入而现场是非交互，则降级为 WARN 并（在 `-NonInteractive` 下）走内存模式失败→中止。

### 3.3 `-NonInteractive` —— 永不阻塞（v0.4.23）
把脚本内所有 `Read-Host` 一律变为「不等待」：能自动则自动，不能自动则打印黄色 WARN + 处置指引后继续（或按策略中止），杜绝「隐窗等人输入 300s 被守卫终止」挂死。`deploy.bat` 一键路径恒定追加此开关。

### 3.4 `-Public` / `-Domain` / `-Email` / `-CertMode` / `-Staging` —— 公网形态（v0.4.27）
只有 `-Public` 开启时，脚本在基础 LAN 部署完成后追加 5 件事；不传 `-Public` 时整体跳过，LAN 默认行为零改变。

| 环节 | 行为 |
|---|---|
| 必填校验 | `-Public` 必须同时给 `-Domain`、`-Email`；`-CertMode` 只能 `acme` 或 `self`。缺任一项立即 `Write-Error` 中止 |
| 证书产物 | `acme`：临时放行 TCP:80 做 HTTP-01 → `yuduan-acme.exe issue --domain .. --email ..`（`-Staging` 追加）→ 产 `certs/acme.fullchain.pem` + `acme.key` → 撤销 :80。`self`：`prepare-public-cert.ps1 -DnsNames <Domain> -CertDir certs`（私有 CA）→ 产 `certs/chain.pem` + `key.pem` |
| 写入 env（幂等 upsert，绝不动 HMAC/PEPPER/SIGN_SEED/DB_DSN） | `YUDUAN_NET_MODE=public`；`YUDUAN_TLS_ADDR=:8443`；`YUDUAN_TLS_CERT`；`YUDUAN_TLS_KEY`；`YUDUAN_PUBLIC_ADDR=https://<Domain>:8443`；`YUDUAN_PUBLIC_DOMAIN`；`YUDUAN_LOGIN_GUARD=1` |
| 防火墙 / 重启 | 确保 TCP:8443 放行（`yuduan-hub-tls`）；写完后 `schtasks /End` 再 `/Run` 让新 env 生效 |
| 连接信息（末尾打印） | 副端端点 `wss://<Domain>:8443/ws/agent`；主端登录页 `https://<Domain>:8443` |

`acme` vs `self` 对副端信任差异：`acme` 用受信任公网证书，副端无需 PIN/CAFILE；`self` 私有 CA 时，副端须带外预置 `YUDUAN_TLS_CAFILE=certs/ca.pem`，并可能配 `YUDUAN_TLS_PIN=<SPKI 指纹>`（脚本解析到 64 位 hex 指纹时一并打印）。**诚实边界**：`public` 形态「必须」经由 `-Public` 进入，不要只手工把 `YUDUAN_NET_MODE=public` 写进 env（会缺证书/信任链，中枢会因 public 缺显式 TLS 证书而拒绝启动）。`-Staging` 只是 ACME 预发验证开关，投产去掉它换正式证书。

### 3.5 `-DiscoveryPort` —— UDP 自动发现端口（v0.4.29 / F-07）
写入 `hub.env` 的 `YUDUAN_DISCOVERY_PORT`（默认 18242），防火墙据此放行 UDP。这是「带外约定」：客户端广播目标端口 ↔ 中枢 UDP 监听端口。广播帧不携带端口、帧格式与 `Ver=1` 不变。合法范围 1..65535，否则脚本立即中止。三端（中枢 env、副端、主端 GUI 设置项）必须配成同一个端口。多实例并存：每个实例及其客户端须配各自【非默认】端口，否则会拿到别的实例的 token 导致 claim 失败。存量部署升级不覆盖已有 env——要换端口须手工在 env 加 `YUDUAN_DISCOVERY_PORT=<端口>`（三端同步）。

### 3.6 `-ResetConfig` / `-AgentDir` / `-TaskName` / `-Remove`
| 参数 | 要点 |
|---|---|
| `-ResetConfig` | 删除既有 `hub.env`、重新随机生成 HMAC/PEPPER/SIGN_SEED。副作用：所有已装副端验签失败，必须重装/重新 claim。仅在想彻底换密钥时用 |
| `-AgentDir` | 同机「中枢+副端」快速路径：指向含 `install-agent.ps1` 的副端 deploy 目录时，脚本读出的 HMAC 自动传给副端（`install-agent.ps1 -Secret <HMAC>`），副端零手填密钥 |
| `-TaskName` | 计划任务名，默认 `YuDuanHub`。多中枢共存需区分时改此值 |
| `-Remove` | 只清理不装：停任务→删计划任务→删三条防火墙规则（`yuduan-hub-plain` / `yuduan-hub-tls` / `yuduan-disc-udp`），保留 `hub.env` 与 `data\`。干净机器上重复执行是 `[SKIP]` 不是报错 |

### 3.7 `-AttestRequire` / `-AttestTrustedMeasurements` —— §9.2 设备证明（**v0.4.33 新增**）
> 背景：v0.4.32 已把 §9.2 设备证明接进 `/ws/agent` 注册握手与持久化，但**部署器未暴露开关**——手工改 `hub.env` 易因未重启服务 / 作用域错配而失效，且无法确认开关是否真正进入运行时（v0.4.32 测试报告 #1/#2 即此根因）。**v0.4.33 收口：开关经支持的部署路径进入运行时 + 启动日志 / 配置 API 可核验。**

- `-AttestRequire`：显式传参才写 `YUDUAN_ATTEST_REQUIRE=1`（未指定保持 `hub.env` 既有值不变，与 `-Public` 行为一致）。重启计划任务后生效。
- `-AttestTrustedMeasurements`：提供才写 `YUDUAN_ATTEST_TRUSTED_MEASUREMENTS`（统一小写 64hex）；留空则仅验签不约束度量。

**启用后中枢行为**（`require_attest=true` 时副端必须附带有效证明，否则拒绝注册 / 不建档）：
1. 三字段（`pubkey`/`attest_sig`/`measurement`）任一为空 → 拒绝（`agent_attest_failed`）；
2. 白名单非空且 `measurement` 不在白名单 → 拒绝（`agent_attest_failed`）；
3. `crypto.VerifyAttestation(pubkey, sig, nonce, token, measurement, chTS)` 失败 → 拒绝（`agent_attest_failed`）；
4. 全部通过 → `attested=true` 落库，注册公钥须与证明公钥一致（防换身份）。

**如何确认开关已生效（v0.4.33 新增可观测，直接回应 v0.4.32 测试报告「待澄清」）：**
- **启动日志**：`yuduan-hub.exe` 启动后 `data\hub.log` 出现「`[hub] 设备证明：强制校验已启用（YUDUAN_ATTEST_REQUIRE=1）；可信度量白名单条目数=N`」；关闭时为「`[hub] 设备证明：强制校验未启用（YUDUAN_ATTEST_REQUIRE=0…）`」。
- **配置 API**：主端/控制台 `GET /api/v1/config`（需 `config:view` 权限）返回的 `info` 段含 `attest_require`(bool) 与 `attest_whitelist_count`(int)。`attest_require=true` 即开关已落地。
- 启用后副端合规注册，设备台账「证明态」列显示「已证明」+「公钥指纹」；旧副端（无证明字段）在强制模式下会被拒绝注册。

## 四、一键 `deploy.bat` 与 `register-task.ps1` 的关系
`deploy.bat` 双击即：① 非管理员则自提权；② 恒定追加 `-NonInteractive`；③ 调用 `register-task.ps1`。因此双击部署遇到「本机需要 PG 口令」不会卡住，而是明确 WARN/中止。**所有开关最终都经 `register-task.ps1` 落到 `hub.env`**——v0.4.33 新增的 `-AttestRequire`/`-AttestTrustedMeasurements` 同样须经此处写入，不要只手工改 `hub.env`（易因未重启 / 作用域错配失效）。

## 五、安装后验证（端到端自检）
`register-task.ps1` 装完即验：① 控制台页面 `GET /` → 200；② 鉴权脚本 `GET /auth.js` → 200；③ 登录接口 `POST /api/v1/login`（admin/admin123；401=鉴权正常仅密码非默认）→ `code=0`。全部通过提示「可登录」，浏览器打开 `http://<中枢IP>:8080`。

## 六、诚实边界 / 已知问题
- **设备证明启用条件**：全网强制 `YUDUAN_ATTEST_REQUIRE=1` 要求全网副端 ≥ v0.4.31；混网旧副端在强制模式下会被拒绝，须先完成全网副端升级再开灰度。
- **度量白名单**：`YUDUAN_ATTEST_TRUSTED_MEASUREMENTS` 逗号分隔 SHA-256 hex；留空 = 仅验签 + 公钥一致；启用白名单须各平台度量值已采集对齐，否则全部拒绝。
- **版本命名**：发布/分发侧文件名须与内容版本一致（v0.4.32 测试曾发现 `F:\YuDuan` 下「v0.4.24」副端实为 v0.4.32 二进制，易误导）。
- **内存模式投产阻断**：一键部署默认拒绝静默内存模式（重启复位）；投产必须配 `YUDUAN_DB_DSN`（v0.4.21+ fail-fast）。
- **Windows exe 签名**：门控签名已就位，未配 `WIN_CODESIGN_PFX`/`PWD` 时 CI 走 `::warning::` 跳过；提供 OV/EV 证书 Secret 后自动生效。
