## 2. N10 根因与修法

**耗时构成（实测 78s）**：stop ~1s（V3 已修）+ 残留清理 0.8s + DeleteService + **标记删除释放轮询 60s 打满**（`YUDUAN_SVC_DEL_WAIT_SECS` 默认 60）→ setup 全量路径 CreateService 撞 1072 → 再轮询 ~15s 至释放。

**关键取舍**：DeleteService 成功即卸载语义达成（服务不再可启动/不占用文件），名称释放只是 SCM 异步回收的可观测尾巴（该机实测恒 >60s）。而 install() 的 1072 等待无法可靠绕开（标记删除中的服务不可启动、复用有被回收竞态）——因此**治本手段是让升级/重装路径根本不 DeleteService**：

1. `install()`：CreateService 撞 **1073（EXISTS）→ OpenService + ChangeServiceConfigW 更新 binPath/显示名/自启/错误控制** → 统一配置失败恢复策略 → 完成。零删除。
2. `run_setup()` 全量路径：服务存在时仅 `stop()`（已停止时瞬时返回）+ 清残留 → 文件替换 → `install()` 复用 → 启动。同目录本就走就地升级快路径；异目录升级从 78s → ~10s。
3. `uninstall()`：释放等待默认 8s；超时打印既有说明（不影响卸载结果，重跑安装器自动处理）。

**被否决的备选**：「标记删除中复用服务对象」（打开句柄虽可阻止回收，但关闭句柄后服务即被回收、配置丢失，且标记删除服务拒绝 StartService）——竞态不可控，否决。

## 6. 边界说明

- **「先卸载再立即重装」组合**（报告 M3 原测法）：卸载后服务名处于标记删除中，`sc create`/CreateService 必须等 SCM 释放（该机实测 ~60-70s）——此窗口由 Windows 异步回收决定，代码无法可靠绕开。**一键升级（跑 setup，不卸载）才是真实升级链路**，本版已全量覆盖为 ≤10s 级；发布质量门口径按报告建议②固化为 CI 的 N10 断言（复用安装 ≤5s + 卸载 ≤10s）。若运维确需「删了立刻同名重建」，可 `YUDUAN_SVC_DEL_WAIT_SECS` 调大卸载侧等待。
- N12（测试台 state 竞态）/N9 属报告方测试台编排（其已改用 job 日志判据），无代码改动。
- `-Memory` 跳过 PG 仅当**无** `-DbDsn` 且**无**既有 hub.env DSN——显式/既有持久化配置不受影响；交互模式未带 -Memory 时行为不变（自动就绪→失败即中止）。
