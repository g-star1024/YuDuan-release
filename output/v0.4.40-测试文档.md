## 2. 根因裁决（源码级铁证）

**结论：报告观察到的现象为真，归因为错。**

| 主张 | 裁决 | 证据 |
|---|---|---|
| 「Windows 副端不读 `YUDUAN_HUB`」 | ❌ 错 | `main.rs:2134-2141` 明确读取，是唯一端点开关 |
| 「端点来自 `agent-config.json` DPAPI 持久化值」 | ❌ 错 | `config.rs:131-135` 该文件只写 `hmacSecret` + `enc`（加密 HMAC 密钥），全源码无持久化端点 |
| 「封 UDP 18242 仍连本地 ⇒ 排除发现抢占 ⇒ 必然有 config 端点」 | ❌ 假两难 | 封发现只让 `discover_ws` 返回 `None`，`main.rs:2196` 的 `if let Some` 不进入，`url` 被**冻结**在上一次的本地值 |
| 我上轮文档「设 `YUDUAN_HUB` 即可走隧道」 | ⚠️ 方向对、漏前提 | 端点只在**服务进程启动那一刻**读一次并固化进内存；必须让服务真正重读/重启 |

**真实根因链**：
1. `--setup`/安装脚本清掉 `YUDUAN_HUB`（`setup.rs:26-31` `DEPLOY_ENV_NAMES` 首项）→ 服务以发现模式启动，`url` 被本地中枢广播的 wss 固化。
2. 改机器级 env 后**服务从未真正重启**（报告 Attempt 3：`sc stop` win32 **1052**、PID 未变）；Windows 服务继承进程创建时刻的 env 快照 → 持旧 `url` 的进程一直连本地 `192.168.2.232:8443`（`openssl s_client -connect` 由 `url` 推导，`main.rs:1009-1016`）。
3. `win_service.rs:210-219` `handle_ex` 收到 STOP 只报 `STOP_PENDING` + 置标志，最终 `STOPPED` 依赖主循环返回（`service_main:252-253`）；主循环阻塞在 `session()` 的 `read_frame()`（在线且无入站帧时永不返回）时永远不上报 → **1052 反复出现**。
4. 因此 **P1-1 与 P2-5 是同一根因链的两面**：不修优雅停止，`--set-hub` 写完也无从生效；不修端点入口，重启后仍会被 `--setup` 清掉回落发现。

**修复设计（不用进程重启，绕开 1052 / 1072 标记删除 60s 窗口）**：
- 新增**独立**持久化端点文件 `agent-hub.json`（不塞进 `agent-config.json`，因 `--setup` 会整文件删后者），明文 `{"hubUrl":"..."}`。
- 端点优先级：`load_hub_url()` **>** `YUDUAN_HUB` env **>** UDP 发现（`--set-hub` 是最新意图，必须压过部署脚本注入的旧 env）。
- `--set-hub` 写文件后发**自定义服务控制码 210**（`YUDUAN_CTRL_RELOAD_HUB`，落在 128~255 用户自定义区间；不受 `dwControlsAccepted` 的 `SERVICE_ACCEPT_*` 位约束，SCM 直接投递 `HandlerEx`）。服务置 `RELOAD_HUB` 并调用 `interrupt_active_session()` 强制关闭在线会话的底层 socket（`shutdown(Both)`）/ openssl 子进程（`kill`），令阻塞在 `read_frame()` 的读循环立即返回 `Frame::Close`；主循环随即重解析端点、把退避 `delay` 置 0 立即重连。**双保险**：控制码失败（权限不足 / 旧版服务 / 非服务前台模式）时，主循环每轮重连都重读 `agent-hub.json`，最迟下一轮自然重连（3–9s + 退避）生效；`win_service::sleep()` 也会因 `RELOAD_HUB` 提前结束长退避。
- 配套 `agent-status.json`（服务写端点/来源/最后连接时间/最后错误/connected/uptime），`--status` 普通用户即可读，补上副端可观测性缺口。
- P2-5：`handle_ex` 立即上报 `SERVICE_STOPPED` + `STOPPED_REPORTED` 单调保护；`install-agent.ps1` 改有界轮询 STOPPED 后再 delete。

### 另一处验收陷阱（P2-4）
`UnreadAlertCount()`（`postgres.go:477-484`）= `SELECT count(*) FROM alerts WHERE read=false`，**与 severity 无关**；且 `AddAlert` 去重 UPDATE（`:425`）不刷新 severity。所以单改 severity **不会**让报告里 id=66 从徽章消失。本版用一条语句同时修：
```sql
UPDATE alerts SET severity='info', read=true WHERE type='rc_timeout' AND severity='warning';
```
`WHERE severity='warning'` 命中不到新 `info` 事件（`wave2.go:368-369`），无振荡；幂等，首次后零写入。

## 3. 改动清单（按文件集）

### 副端 Rust（A 档：P1-1 + P2-5 + 可观测性）
- `rust/agent/src/config.rs`：新增 `config_dir()` / `hub_file()` / `status_file()`，复用 `config_file()` 的目录解析（含 `YUDUAN_CONFIG_FILE` 覆盖）；`load_hub_url()` / `save_hub_url()`（tmp+rename 原子写、trim、空值拒绝、损坏文件容错）；`delete_config_file()` 只删 `agent-config.json`，不误删端点。
- `rust/agent/src/config.rs`（状态快照）：`AgentStatus` + `status_note_connect() / connected() / error()` + `format_agent_status()`，原子写 `agent-status.json`；`started_at` 首次固化、跨更新不变；新增 2 个单测（端点 roundtrip + 重装清密钥不清端点 / 状态 started_at 保持）。
- `rust/agent/src/main.rs`：CLI 改为 `enum CliCmd`（新增 `--set-hub <url>` 位置参数、`--help/-h`）；`valid_hub_url()` 校验 ws/wss 前缀、拒绝空白/引号/控制符；未提权时 `relaunch_elevated()` UAC 重拉自身并原样携带参数；`resolve_hub()` 优先级链 `agent-hub.json > YUDUAN_HUB > UDP 发现`；重连循环每轮重解析端点、`RELOAD_HUB` 时 `delay=0`；新增 `ACTIVE_INTERRUPT`（`Tcp(TcpStream)` / `Tls(Arc<Mutex<Child>>)`）句柄注册表 + `interrupt_active_session()` / `request_hub_reload()`，使在线会话可被控制码打断；`WsClient.tls_child` 改 `Arc<Mutex<Child>>` 以便 SCM 线程 kill；显式端点存在时跳过 UDP 发现漂移。
- `rust/agent/src/win_service.rs`（P2-5 闭环）：
  - `handle_ex` 收到 STOP/SHUTDOWN **立即上报 `SERVICE_STOPPED`**（不再只报 `STOP_PENDING` 等主循环返回），并 `interrupt_active_session()` 断开在线会话；新增 `STOPPED_REPORTED` 原子标志 + `report()` 状态单调保护，防止 `service_main` 尾部把 STOPPED 倒退成 STOP_PENDING —— 这才是 1052 的真正根因。
  - 自定义控制码 `YUDUAN_CTRL_RELOAD_HUB=210` → `crate::request_hub_reload()`；`notify_hub_changed()` 用 `SERVICE_USER_DEFINED_CONTROL` 权限打开服务并 `ControlService` 发码，失败返回 Err 但**不影响已落盘端点**（文件轮询兜底）。
  - `status()` 先读 `agent-status.json`（端点/来源/最近连接/错误/connected/uptime），再叠加 SCM 状态 + PID；SCM 权限从 `ALL_ACCESS` 降为 `CONNECT|QUERY_STATUS`，普通用户可读；查询失败也把文件内容带回 `Err` 文本，`--status` 无论 Ok/Err 都打印，绝不空手而归。
  - `sleep()` 改 250ms 粒度轮询，STOP / RELOAD_HUB 均可提前结束长退避。
- `rust/agent/src/setup.rs`：`--setup` 与就地升级路径只删 `agent-config.json`，注释明确**保留** `agent-hub.json`（重装不抹掉运维远端端点）。
- `rust/agent/deploy/windows/install-agent.ps1`：`sc stop` 后改**有界轮询（15s）等真实 Stopped** 再 delete，规避 1072 标记删除 60s 窗口；重装只删 HMAC 密钥配置、保留端点；卸载才清端点/状态文件；显式传 `-HubUrl` 时清掉持久端点让 env 生效（见 §附）。

### 部署器 PowerShell（B/C/D 档，单文件）
- `dev/deploy/hub/register-task.ps1`：
  - P1-2：`version = $script:DeployVersion`，优先 `-BuildVersion`，否则读 `yuduan-hub.exe` PE FileVersion，异常回退 `unknown`；赋值在所有 `Write-DeployResult` 调用点之前。
  - P1-3：抽出 `Install-PortablePg()` 可复用流程；复用本机 PG 因 `PG_AUTH_REQUIRED` / `PG_ROLE_EXISTS_NO_PWD` 失败时清根因码并**自动降级**自带 trust PG（5433..5442 备用端口），绝不重置存量库口令；`-PgSuperPwdStdin` 从 stdin 读一行口令、`PGPASSWORD` 在 `finally` 中无条件清除；`$script:PG_PORT` 作用域修正保证 DSN 用对端口。
  - P3-7：在 installDir + 父目录两层 `Get-ChildItem -Recurse -Depth 2 -Filter 'pgsql-*-binaries.zip'` 自动发现离线包，命中写 `$script:PG_BUNDLE`（脚本级，避免函数内局部副本）。
  - P3-8：`-m 1800 → -m 600`、`& curl.exe -s -w` 把字节数/耗时写 stdout 作分段进度（避开 `cmd /c` 对 `%` 的展开与 EAP=Stop 下原生 stderr 问题）；**下载失败**与**解压后缺 `pgsql\bin\initdb.exe`** 两条失败路径均显式置 `PG_INSTALL_FAILED` + curl exit/统计诊断，不再被末尾聚合误报成 `DSN_MISSING`。
  - **【收口期补齐·范围外】** 公网段 `schtasks /End` 后补 `taskkill /IM yuduan-hub.exe /F`（与基础流程 D-08 同口径），避免孤儿 hub 占住 :8080/:8443 导致 `/Run` 拉起的新进程端口冲突、公网 env 不生效。此项不在报告 9 项内，为实现工回报的一行级已知缺陷；因同类写法已在基础流程验证、且 PS1 不参与 CI 编译，随版一并收口。
  - `deploy.bat` 无需改（52 行 `%*` 透传）。

### 中枢 Go（B/C 档）
- `dev/internal/store/postgres.go`：migrate 末尾加 rc_timeout 降级 UPDATE；`devices` 加 `source_addr` 列（`CREATE TABLE` + 幂等 `ALTER TABLE`）；`deviceCols` 28→29；`Upsert` 加 `source_addr=CASE WHEN EXCLUDED.source_addr <> '' THEN ... ELSE devices.source_addr END` 守卫；`rowToDevice` `get(28)`。
- `dev/internal/store/store.go`：`Device.SourceAddr`（`json:"source_addr,omitempty"`）；MemStore 重连分支仅在非空时刷新，语义与 PG 守卫一致。
- `dev/internal/hub/hub.go:966-973`：注册时用 `loginGuardClientIP(r)`（支持 `YUDUAN_TRUST_PROXY=1` / XFF）填 `SourceAddr`，每次注册重取，不被 identityReuse 覆盖。
- `dev/internal/hub/export.go` / `dev/proto/schema.sql`：CSV/XLSX 导出新增「连接来源」列、冻结 schema 对齐。
- **不改** `proto.RegisterPayload`（服务端观测值不进副端载荷）与 devices API handler（整体序列化 Device 自动带出新字段）。

### 主端（B/C 档）
- `main/src-tauri/src/lib.rs`：`#[cfg(not(unix))]` 补 Windows 文件日志（`%APPDATA%\YuDuan\logs\main.log`）：`AsRawHandle` 取 HANDLE → libc `open_osfhandle(handle as isize, O_WRONLY|O_APPEND)` → `dup2(fd,1)` / `dup2(fd,2)`；`_log_file` 绑定进程生命周期避免 CRT fd 与 FILE 共享的 HANDLE 被提前关闭；全程 best-effort，绝不 panic。
  - ⚠ **符号名订正**：Rust libc 0.2.191 的标识符是 `open_osfhandle` / `dup2` / `O_WRONLY` / `O_APPEND`（**C 符号才带前导 `_`**），且 `_open_osfhandle` 必须带访问模式位——单给 `O_APPEND` 会按 `O_RDONLY`(=0) 解读，与可写句柄不符，故必须 OR `O_WRONLY`。
- `main/src-tauri/Cargo.toml`：`libc` 从 `[target.'cfg(unix)'.dependencies]` **移到通用 `[dependencies]`**，否则 Windows 分支无法解析 `libc::`。已用双 Windows target 临时 crate 类型检查通过。
- `main/src-tauri/src/hub_client.rs`：**关键接线订正（初版规格漏项）** — Rust `Device` 结构体补 `#[serde(rename="source_addr", default)] pub source_addr: String`。前端 `invoke("hub_devices")` 经此结构体反序列化，serde 默认丢弃未知字段；若不补，Go 新增的 `source_addr` 在 Rust 层被静默丢弃、台账恒显「—」，V10 验收不可能达成。
- `main/src/api.ts`：`Device.source_addr?: string`（可选，兼容旧 hub）。
- `main/src/pages.tsx`：设备详情加「服务端观测源地址」行（标签常显、缺省「—」、带 CopyBtn）；表格仅在 `source_addr` 存在且 ≠ 自报 ip 时以小字副行显示（LAN 场景二者相同则不显示，避免噪音）；搜索过滤纳入；**自报 ip 行原封不动**。

## 附：决策与权衡

| 决策 | 被否决方案 | 否决理由 |
|---|---|---|
| P1-1 按真实根因链修，不按报告结论 | 按报告「`agent-config.json` 存端点、加 `--set-hub` 覆盖 config 优先级」实现 | 该 config 只存 DPAPI 加密 HMAC 密钥，根本无端点字段；照此实现等于改一个不存在的前提，M8 仍失败 |
| `--set-hub` 用「持久化文件 + 运行期控制码重载」 | 「写 config 后 `sc stop` + `start` 重启服务」 | 现网 `sc stop` 返回 1052、PID 不变，重启路径本身是坏的；且 1072 标记删除有 60s 窗口。控制码方案绕开两者，且在线会话可打断 |
| 端点优先级 `hubUrl > env > 发现` | `env > hubUrl > 发现` | 报告 Attempt 4/5 的机器级 env 是部署脚本注入的旧值；若 env 优先，用户 `--set-hub` 的最新意图会被旧 env 压过，缺陷复现 |
| 端点存**独立** `agent-hub.json` | 塞进现有 `agent-config.json` | `--setup`/重装会整文件删除 `agent-config.json`（`setup.rs:178-185,218-225`），远端端点会被每次重装抹掉 |
| P1-3 默认自动降级便携 PG | 仅提供口令参数，要求运维显式传 | 报告验收口径是「纯一键 → 退出码 0」，纯参数方案仍需人工介入，不满足；口令入参仅作可选逃生舱，且走 stdin 避免落命令行/日志 |
| P2-4 一条 UPDATE 同时改 severity + read | 只改 severity | 徽章只数 `read=false`，只改级别不会让 id=66 从徽章消失，会被判失败 |
| P3-9 用 `loginGuardClientIP(r)` | 裸 `r.RemoteAddr` | Cloudflare 隧道/反代下 RemoteAddr 塌缩为 127.0.0.1；前者支持 `YUDUAN_TRUST_PROXY=1` 采信 XFF 首段，才能拿到 CF 边缘 IP |
| P3-9 不改 `proto.RegisterPayload` | 让副端上报 source_addr | 服务端观测值按定义不应来自副端自报（自报正是待修的问题） |
| **【实施期订正】** 补 Rust `hub_client::Device` 的 `source_addr` 透传字段 | 只改 Go 后端 + TS 前端，不动主端 Rust 结构体 | 前端 `invoke("hub_devices")` 的返回经 Rust `hub_client::devices()` 反序列化；serde 默认丢弃未知字段，Go 新增的 `source_addr` 会在 Rust 层被静默吞掉、台账恒显「—」，V10 验收不可能达成。属**初版规格漏项**，实现工主动发现并补齐，主理人裁决保留 |
| **【实施期订正】** Windows 日志用 libc Rust 标识符 `open_osfhandle`/`dup2`/`O_WRONLY|O_APPEND` | 照初版规格写 C 符号名 `libc::_open_osfhandle` / `_dup2` / `_O_APPEND` | Rust libc 0.2.191 无这些标识符（`#[link_name]` 才是 C 名），照抄编译失败；且单给 `O_APPEND` 会被按 `O_RDONLY`(=0) 解读，必须 OR `O_WRONLY`。实现工核 Cargo.lock 源码 + 双 Windows target 类型检查后订正 |
| **【实施期定案】** 端点热切换用自定义控制码 **210** | 初版规格写的 `SERVICE_CONTROL_PARAMCHANGE` | 标准 `PARAMCHANGE` 受 `dwControlsAccepted` 约束且语义被其他组件复用；用户自定义码 128~255 不受 `SERVICE_ACCEPT_*` 位约束、SCM 直接投递 `HandlerEx`，且不与系统控制码冲突。实现按 210 落地，本文档 §2/§3 已同步订正 |
| **【实施期定案】** 重装保留 `agent-hub.json`、仅显式 `-HubUrl` 时才清 | 重装一律清除所有落盘配置 | 报告 M8 的痛点正是「每次重装把远端端点抹掉、退回 UDP 发现」；但显式传 `-HubUrl` 表示本次要覆盖端点，若不清旧文件，会因其优先级高于 env 导致「改了却不生效」，故二者按语义区分（卸载则属彻底移除，清端点/状态） |
