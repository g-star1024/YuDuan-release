# 御端 v0.4.32 规划 — 设备证明（§9.2）中枢接线

> 状态：**开发完成，待发版**（中枢接线已落地并通过单测 + 全模块回归）。
> 前序：v0.4.31 已完成协议契约基座（副端每设备 Ed25519 密钥 + 二进制度量签名 + 跨语言黄金向量 + `crypto.VerifyAttestation`），但中枢侧零调用点。本版把验证落进注册握手。

---

## 1. 目标与范围

把 §9.2 设备证明从「契约基座」升级为「中枢强制执行点」，在不破坏 LAN 默认形态的前提下提供灰度强制证明能力：

- **中枢接线点（本版落地）**：`dev/internal/hub/hub.go` 的 `/ws/agent` 握手与注册两处 + `dev/internal/store/*` 持久化两列。
- **副端（Rust）**：**无需改动**——v0.4.31 已实现 `require_attest=true` 时生产 `pubkey/attest_sig/measurement` 三字段，并以中枢下发的 `auth_challenge.ts`（原始秒）为 `ts` 签名，规范串 `"yuduan-attest|nonce|token|measurement|ts"` 与中枢逐字节一致。
- **协议（proto）**：**无需改动**——`AuthChallengePayload.RequireAttest`、`AuthResponsePayload.Pubkey/AttestSig/Measurement`、`RegisterPayload.AgentPubkey` 已在 v0.4.31 定义且 `omitempty`。
- **主端（Tauri/React）**：**本版不动**；后续建议在设备台账增加「证明态 / 公钥指纹」只读展示列（见 §6 待办）。

### 默认关闭、零回归铁律
- `YUDUAN_ATTEST_REQUIRE` 默认不启用 → 中枢 `RequireAttest=false`，挑战不带 `require_attest`，旧副端（无证明字段）逐字节兼容放行，LAN 形态完全不变。
- 启用（`=1`）后：未带证明 / 验签失败 / 度量未命中白名单 → 握手即拒（连接断开、不建档），审计落 `agent_attest_failed`。

## 2. 接线设计

### 2.1 灰度开关与白名单（Hub 字段，构造于 `NewHub`）
```go
attestRequire            bool              // YUDUAN_ATTEST_REQUIRE=1 → 强制要求副端证明
attestTrustedMeasurements map[string]bool  // YUDUAN_ATTEST_TRUSTED_MEASUREMENTS 逗号分隔 SHA-256 hex；非空时度量须命中
```
配套 helper：`envBool(key)`（1/true/t/yes/y/on 即 true）、`parseTrustedMeasurements(s)`（逗号分割、trim、去空、小写）。

### 2.2 接线点 1 — 下发挑战（`handleAgentWS`）
下发 `AuthChallengePayload` 时置 `RequireAttest: h.attestRequire`，并捕获 `chTS := time.Now().Unix()` 供后续验签（**同一连接同源，避免时间漂移**）。

### 2.3 接线点 2 — 握手验收（HMAC 通过后）
HMAC 校验成功后，若 `h.attestRequire`：
1. 三字段（`pubkey/attest_sig/measurement`）任一为空 → 拒；
2. 白名单非空且 `strings.ToLower(measurement)` 未命中 → 拒；
3. `crypto.VerifyAttestation(pubkey, sig, nonce, ap.Token, measurement, chTS)` 非 true → 拒；
4. 通过则 `attested=true` 并记下 `apPubkey`（与 `claimedToken` 同级生命周期）。

### 2.4 接线点 3 — 注册落库（`TypeRegister` 分支）
- 若 `attested && p.AgentPubkey != apPubkey` → 拒绝（防「证明用 A 密钥、注册报 B 密钥」换身份）；
- `dev.AgentPubkey = p.AgentPubkey`；`dev.Attested = attested`。

### 2.5 持久化（store）
- `Device` 新增 `AgentPubkey string` / `Attested bool`；
- PG：`deviceCols` 追加 `agent_pubkey,attested`；Upsert 位置占位符扩至 `$27`，ON CONFLICT 同步两列；`rowToDevice` 索引 26/27 解析；`migrate()` 幂等加列（`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）；
- MemStore.Upsert：仅在 `d.AgentPubkey != ""` 时刷新两字段（**旧副端重连不得清空既有公钥 / 证明态**）。

## 3. 测试结论（已落地）

新增 `dev/internal/hub/attest_test.go`（8 例）+ `dev/internal/store/memstore_test.go`（3 例），覆盖：

| 用例 | 结论 |
|---|---|
| 强制模式 + 旧副端（无证明） | 拒，不建档 ✅ |
| 强制模式 + 合规证明 | 接受，台账 `Attested=true` / `AgentPubkey` 正确 ✅ |
| 强制模式 + 篡改签名 | 拒，不建档 ✅ |
| 强制模式 + 白名单未命中 | 拒 ✅ |
| 强制模式 + 白名单命中 | 接受 ✅ |
| 强制模式 + 证明/注册公钥不一致 | 拒，不建档 ✅ |
| 默认 LAN + 旧副端 | 接受（兼容）✅ |
| 默认 LAN + 带证明字段 | 接受（无害）✅ |
| MemStore 重连不空公钥 / 换密钥刷新 | ✅ |

全模块 `go test ./...` 通过；`go build ./...` / `go vet ./...` 干净。

## 4. 部署环境变量（新增，默认关闭）

| 变量 | 默认 | 作用 |
|---|---|---|
| `YUDUAN_ATTEST_REQUIRE` | 关闭 | `=1` 强制要求副端设备证明，否则拒绝注册 |
| `YUDUAN_ATTEST_TRUSTED_MEASUREMENTS` | 空（不启用） | 逗号分隔的可执行文件 SHA-256 hex 白名单；非空时度量须命中 |
