## 2. 根因（代码级铁证）

- **Tauri v2 同步命令跑在 UI 主线程**（已查证："commands without async run on the main thread"）。主线程同时驱动原生窗口消息循环 + IPC。
- 主端所有中枢命令都是同步 `fn`，内部走 `http.rs::request`——**纯 std 同步阻塞 HTTP**（`TcpStream` 手写，每次 `connect_timeout` + 读满响应，GET 超时 10s / POST 20s）。
- 前端多个轮询同时打主线程：设备列表每 5s（`App.tsx:245`）、未读告警每 10s（`App.tsx:255`）、远控会话/审批/录像每 10s 三个并行 `invoke`（`pages.tsx:1608-1621`）。
- 经隧道（RTT≈1.5–1.7s）：单次轮询冻结主线程 ~1.5s；远控页 3 个并行 invoke 串行排队 → 每 10s 冻结 ~4.5s；隧道抖动时 socket 等到 10–20s 超时 → 冻 10–20s。
- **局域网低延迟时几乎无感**，隧道/远端高延迟时彻底暴露——与用户"换隧道才卡"的现象完全吻合。

### 改动清单（lib.rs）
| 命令 | 阻塞源 |
|---|---|
| `hub_login` / `hub_change_password` / `hub_devices` / `hub_device_cmd` | HTTP |
| `hub_check_update` / `hub_api_get` / `hub_api_post` / `hub_api_delete` | HTTP |
| `hub_export` / `hub_upload_software` | HTTP（+ 落盘/上传） |
| `discover_hub` | UDP 广播 |

均改为 `async fn` + `tauri::async_runtime::spawn_blocking(move || { … })`；前端 `invoke()` 契约不变。
**未改**：`pick_file`（已 async）、`local_hostname`（纯计算）、`rc_*`（会话控制，瞬时锁或走独立会话线程，不阻塞主线程）。
