## 三、实测验收指引

### A1 副端就地升级链（核心回归，第十三轮失败场景复刻）
1. 在已装 v0.4.21 副端的机器上发起一次远控（让 rc-helper 在用户会话拉起），或任由副端运行即可；
2. **不杀任何进程**，直接以管理员重跑 v0.4.22 安装器（`--setup`）；
3. 预期：一次通过 exit 0（安装器先强杀残留进程→删服务→等名字释放→重建），不再出现「60 秒后仍 1072、升级变卸载」；
4. 验证：`--status` 显示服务 Running；中枢 `/api/v1/devices` 该设备 online=true 且 ver=0.4.22，指纹 ID 不变。

### A2 1072 失败文案（防御路径）
- 人为制造占用（如暂停服务但保留进程）使升级撞 1072 时，文案应含「请先结束所有 yuduan-agent.exe 进程（任务管理器，或 taskkill /F /IM …）再重跑安装器即可恢复」，不再是旧版笼统「重跑即可恢复」。

### B1 PG 自动就绪·干净机全链（推荐在测试服先卸 PG 再跑）
1. `deploy.bat` 一键部署（无 hub.env、无 PG、5432 空闲）；
2. 预期输出序列：`检测宿主机 PostgreSQL…` → `自动下载官方便携包（约 314MB）` → `解压 PostgreSQL` → `初始化 PG 数据目录` → `[OK] PostgreSQL 已就绪（yuduan-pg 服务，仅监听 127.0.0.1:5432，开机自启）` → `[OK] 已自动创建 yuduan 角色/库` → `[OK] 已写入 PostgreSQL 持久化配置`；
3. 验证：`sc query yuduan-pg` RUNNING；`hub.env` 含 `YUDUAN_DB_DSN=postgres://yuduan:<hex24>@127.0.0.1:5432/yuduan?sslmode=disable`（hex 口令，无特殊字符）；中枢日志出现「持久化后端：PostgreSQL」；重启中枢后 admin 口令与设备数据保持。

### B2 离线捆绑路径（内网无公网）
- 预置 `pgsql-windows-x64-binaries.zip`（EDB 下载）到中枢安装目录 → 重跑 deploy.bat → 应直接走「检出本地 PostgreSQL 便携包（离线安装）」不解网。

### B3 已有 PG 复用
- 宿主机已装 PG（Program Files 或 PATH 或 postgresql* 服务）→ 应打印「检出本机 PostgreSQL：<路径>（复用，不重装）」；trust 认证时全自动建号；密码认证时询问一次 postgres 口令；口令错误/拒绝则回退手工 DSN。

### B4 DSN 交互防呆（回退路径）
- 回退交互时提示应含三条要点：①示例只是模板直接粘贴必失败 ②密码纯 ASCII/URL 编码 ③须先建 yuduan 角色与库。

## 四、遗留与说明

- `register-task.ps1` 语法校验：PowerShell 7.4.6 Parser::ParseFile → **SYNTAX OK**（0 错误）；函数级冒烟（Find-PgBinDir/Invoke-Psql/Start-OwnPg 空跑）路径全部干净返回；Windows 实机冒烟以 B1 为准。
