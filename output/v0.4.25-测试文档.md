### 2.2 「缺省等价」门禁（零 LAN 影响的唯一证伪方式）

> system-architect 裁决：**未配置任何新增变量时，代码路径须与今日逐字节等价**。

- 判定方式：**A/B 基线对比** —— 用 `git archive f737ae2` 导出 v0.4.24 到 /tmp 隔离目录，与本轮交付 commit **各自跑同一组脚本**，逐项比对 PASS 计数与输出；**不允许「新增失败但整体通过」**。
- 发版门禁脚本全绿：`dev/e2e_rust.py`、`dev/e2e_claim.py`、`dev/e2e_tauri_tls.py`、`dev/e2e_regauth.py`、`dev/e2e_m6.py`、`dev/e2e_wave5b.py`（后两者覆盖登录与分发）。
- **`dev/e2e_rc_signing.py:188` 用 `YUDUAN_TLS_ADDR=""` 关闭 TLS 的语义本轮不得改变**（否则与开发机上已运行的中枢抢 :8443，会造成整轮 e2e 假失败）。
- 静态断言：三个默认端口字面值 `:8080` / `:8443` / `18242` 未改；`Ver=1`；新增代码无内置公网域名/IP；契约文件 `dev/internal/proto/wave4.go` 零 diff。
- **A 方案专项断言（裁决 ⑪）**：**不显式设置** `YUDUAN_HUB_ADDR` 时，LAN 的 `:8080` 占用回退链（8081/8082/8083/18080）与 UDP 广播应答帧与 `f737ae2` 基线**逐字节等价**；**显式设置**且端口占用时 `dev/cmd/hub/main.go:321-322` 判 `addr != ":8080"` → `log.Fatalf` 直接退出（禁回退，零代码即可满足，无需新开关）。见 C-58。
- **证书侧「缺省等价」专项断言（P0，零影响回归头号陷阱）**：当 `YUDUAN_TLS_CAFILE` / `YUDUAN_TLS_PIN` **两变量全不配或均为空串**时（**SNI 不是变量**，一律从 URL authority hostname 推导，裁决 ⑨）—— ① **claim https 通道的 `s_client` 参数除无条件新增的 `-servername` 外，与 v0.4.24 逐字节一致**（`-servername` 只设 SNI、不开启校验，是本轮唯一无条件新增参数，A/B 比对须显式排除它，否则会假阴性；口径分歧见 §1.2 留痕）；② **副端仍能注册成功**（claim 拿到 `hmacSecret`）；③ 严格校验路径仍不校验、一个 verify 参数都不追加（`apply_verify_args_none_is_noop` / `plan_verify_default_adds_nothing` 单测断言）；④ **除 `-servername` 外全部 verify 参数（`-CAfile` / `-verify_return_error` / `-verify_hostname` / `-verify_ip`）必须「显式 CAFILE/PIN 存在才追加」**，`config.rs:263-267` 的 `stderr` 也仅在 `plan.is_some()` 时才 `piped()`；⑤ **四条存量路径既有参数一字不动**（二者皆无 / 仅 PIN 的 `pinned_ca` 自签兼容 / 仅 CAFILE / 二者皆配），尤其仅 PIN 路径不能加主机名校验——自签证书 SAN 仅 `localhost/127.0.0.1/::1`（`dev/internal/tlsutil/tlsutil.go:47-48`），LAN 副端普遍用 `wss://192.168.x.x:8443`，无条件加 `-verify_ip` 必然校验失败 → 一次性打断全部自签 LAN 部署（复盘 S-8，亦为裁决 ⑬ 依据）；⑥ **硬约束「失败即 `Err`、绝不静默连上或降级回不校验」**（system-architect 追加）：显式锚存在但校验失败时，`-verify_return_error` 使 `s_client` 非零退出、stdout 无 HTTP 响应 → `config.rs:290-298` 走 `claim https 响应格式异常: claim_tls_hint(stderr)` 返回 `Err`，不得吞掉失败继续注册；⑦ wss 通道同一套 `plan_verify`，参数口径与 claim 一致；⑧ Go 侧两 env 均未配时 TLS 配置与 `wave3.go:175` 等价（`InsecureSkipVerify:true`）。**严格校验不得设为默认**；`e2e_m6.py:51-53` / `e2e_claim.py:11` 的 `CERT_NONE` 走 Python 侧、不经副端 claim，不受影响。

> **适用范围不止 claim，但仅限副端双通道**：现有 wss 通道 `rust/agent/src/main.rs:951-971` 是 `s_client -connect <addr> -servername <sni_host> -quiet -ign_eof` + `apply_verify_args(plan)`。C-13 / C-46 必须同时验 **claim https 与设备 wss 两条副端通道**；**主端 PIN-only 通道不在其中**（`main/src-tauri/src/tls.rs:108-110` 是 `danger_accept_invalid_certs(true)` + 仅 SPKI 比对，只有 CAFILE 路径 native-tls 自带 hostname 校验），单独登记【待确认】/遗留（§11.3）。
> ⚠️ **能力降级声明（老版本 OpenSSL 退路）**：`tls::verify_server_pin` / `fetch_chain_pem`（`tls.rs:88-100`）**只抓链并比对叶证书 SPKI，不做 SAN / hostname 校验**——这不是主机名校验的等价替代。验收时**不得把「SPKI 通过」虚报为「SAN 校验通过」**；主机名校验本轮整体不纳入（裁决 ⑬）。`-verify_hostname`/`-verify_ip` 需 OpenSSL ≥1.1.1【待确认三平台目标 openssl 版本与参数支持性，§11-23 / 附录 B】。

> **C-47 状态（裁决 ⑦）**：`YUDUAN_TLS_PIN_NEXT` 全仓 Grep 零命中（`rust/agent/src` 内只有 `sha256.rs` 的 `rotate_right` 与 v0.4.20 密钥轮换自愈，与 pin 轮换无关）。**本轮显式否决、不实现**，删掉所有【待实现/待确认】标注，避免放行被误判失败；已移入 §11.3「遗留与观察」，并转为「教程证书轮换口径文档核证」用例。

## 6. AI 专项与规则引擎诚实性

本项目三端为 Go / Rust / TS 传统实现，**无 LLM / 智能体输出能力，AI 专项不适用**（无需 Prompt 回归、流式中断、成本波动测试）。代之以等价的「规则引擎诚实性」评测：

## 附录 C：SAN 主机名校验遗留的四条前置约束（裁决 ⑬，system-architect 转达主理人最终裁决）

本轮 **SAN 主机名校验（openssl `-verify_hostname` / `-verify_ip`）整体不纳入 v0.4.25**，登记「遗留与观察」。后续任何版本若启用，必须**先全部满足**以下四条，否则违反 Gate「默认 LAN 零影响」与铁律 5 诚实回告：

1. **先有三平台 openssl 版本矩阵实机验证**：macOS 自带 LibreSSL、Windows / Linux 常驻实现不一，`-verify_hostname` / `-verify_ip` 参数支持性**未实测、不得臆断**；不支持时必须按铁律 5 诚实回告 `unsupported+reason`，**不得做成静默降级的假开关**。
2. **仅显式信任锚（CAFILE/PIN）路径启用**：除 `-servername` 外全部校验参数只在显式配置存在时追加，**绝不无条件加**；DNS 名用 `-verify_hostname`、IP 用 `-verify_ip`，取值与 `-servername` 同源。
3. **四条存量路径参数一字不动**：PIN+CAFILE / 仅 PIN / 仅 CAFILE / 二者皆无；**尤其仅 PIN 的 `pinned_ca` 自签兼容路径不得加主机名校验**（自签 LAN SAN 仅 `localhost/127.0.0.1/::1`，LAN 副端普遍用 `wss://192.168.x.x:8443`，无条件加 `-verify_ip` 必然握手失败 → 一次性打断全部存量自签部署，复盘 S-8）。
4. **先按 `ca issue-server -dns/-ip` 重签含 IP SAN 的证书**：`dev/cmd/hub/main.go:182-187` 私有 CA 自动签发只带 `[]string{os.Hostname()}` 的 **DNS SAN、无 IP SAN**，存量「私有 CA + IP 直连」客户若追加 `-verify_ip` 会一次性握手失败，属需变更窗口的运维动作。

> **采纳的决定性理由（写入决策与权衡，§1.2 裁决 ⑬）**：① 自签 LAN 半无条件加 `-verify_ip` 会打断全部存量自签部署，违反 Gate「默认 LAN 零影响」；② 三平台 openssl 实现不一，做成静默降级的假开关违反铁律 5 诚实回告。本轮必落的 `-servername`（仅设 SNI）+ 显式 CAFILE/PIN 下的 `-CAfile -verify_return_error` **已提供身份锚**，主机名校验属**纵深防御层、非准入条件**。
