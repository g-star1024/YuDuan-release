## 2. 缺陷A：主端跨机远控不可用（高危）——修复与根因修正

### 2.1 对第九轮报告结论的重要修正（基于开发方复测实证）
- **传输层与架构无罪**：开发方以脚本 1:1 复刻主端 auto 模式协商（P2P 监听 + `rc_select{transport:"p2p",media_addr}` + `rc_offer` 候选广播），在中枢机（副端 .232）↔ 主端机（.124）间实测：**副端 0.234s 拨入 P2P、首帧 1.370s、30s 434 帧/54.5MB，零失败**。副端是**拨号方**（ICE-lite 单侧监听模型），报告"副端媒体通道仅绑回环、对外无可连地址"不构成 P2P 不可达。
- **13:20 的 0 帧窗口与缺陷B 时间线吻合**：netstat 显示副端对外无任何连接 = 副端从未拨号 = 副端服务正处于「1072 升级变卸载」的服务消失窗口（rc_request 发往已死连接，rc_ready 永不到来 → 主端无限转圈 → viewer WS 挂 16.86s 后被手动关闭）。"主端 P2P 失败未回退"亦非事实（副端拨号失败即落中继且帧不断流），但主端确实缺少**就绪超时**与**兜底回退**，本版补齐。

### 2.2 本版修复（`main/src-tauri/src/media_session.rs` 双看门狗）
| # | 修复 | 行为 |
|---|---|---|
| ① | **rc_ready 15s 看门狗** | 被控端离线/升级中断时不再无限转圈：15s 内未就绪 → 状态条明确报错「被控端无响应（15s 内未就绪，可能离线或正在升级维护），请稍后重试」并结束会话。敏感设备审批期间计时自动重置（审批耗时不受限） |
| ② | **auto 模式 P2P 5s 看门狗** | `rc_select` 宣告 p2p 后 5s 内既未直连成功也无任何媒体帧 → 自动重发 `rc_select{transport:"relay"}` 强制回落中枢中继（报告建议①），状态条提示「P2P 直连不可达，已自动回退中枢中继」——不再依赖用户手动切「中继」 |

## 3. 缺陷B：副端升级安装器 win32 1072（高危）——修复（`rust/agent/src/win_service.rs`）

| # | 修复 | 说明 |
|---|---|---|
| ① | `uninstall()` 删除后**等名字真正释放** | DeleteService 返回成功 ≠ 名字立即可用（SCM 句柄未全释放 → 标记删除）。现轮询 `OpenServiceW` 直到返回 1060（不存在）再返回，最多 10s，保证「卸载→安装」时序安全 |
| ② | `install()` 对 1072 **轮询重试** | 同名 CreateServiceW 遇 1072 时按 500ms × 20（10s）重试，期间名字被释放即创建成功（日志可见「服务名已释放，服务创建成功」） |
| ③ | **错误文案纠偏** | 「可能需要管理员权限」具有误导性（现场本就提权运行）。现按错误码区分：1072 → 标记删除待清理（关句柄程序/重启后重试）；5 → 明确提示管理员权限；其余通用 |

## 4. 问题3：采集异常通知刷屏（低）——60s 冷却（`rust/agent/src/rc.rs`）

- 同一会话内采集异常通知间隔 **≥60s**（首次必发；每 10 次失败的重发需距上次通知 ≥60s）；「已恢复」回告仅在该次异常确实发过通知时才发（配对、不额外刷屏）。
- 注：报告问题3 的实测引文是 v0.4.15 旧措辞（首轮安装误装 v0.4.15 二进制），v0.4.16 措辞+恢复回告与 v0.4.17 冷却叠加后，周期刷屏应消失。

## 6. 实机测试指引（第十轮验收）

1. **跨机远控（核心）**：主端机登录 → 副端在线 → 点远控（默认 auto）→ 预期 ≤2s 出真实桌面画面；工具栏 QoS 应显示 P2P 直连（若 P2P 不可达则 ≤5s 自动回退中继并有提示）。**任何情况下转圈不超过 15s**——超时必有明确报错文案。
2. **副端升级链路（核心）**：用官方包装从 v0.4.16 升级到 v0.4.17（或先装 v0.4.16 再升）→ 预期服务平滑替换、无 1072、升级后服务 Running 且 ver=0.4.17；若旧版本 NOT_STOPPABLE 强杀路径触发，日志应出现「等待服务名从标记删除中释放」或「服务名已释放，服务创建成功」。
3. **采集通知**：远控全程画面正常时不应出现周期性「采集不可用」通知；若环境确有短暂失败，单次「暂时不可用→已恢复」成对出现，间隔 <60s 内不重复。
4. **回归抽查**：敏感设备二次审批全链路（用 `{"approve":true}`）、viewer 403(4003)、meta 部分更新、自检③ [PASS]。
