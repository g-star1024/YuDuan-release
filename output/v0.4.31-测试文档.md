# 御端 v0.4.31 · 中枢配置 API + 主端面板 + 安全 P1 + 安全 P2 — 测试与发布核验文档

> v0.4.31 范围由用户拍板：**一次性覆盖 配置 API + 主端面板 + P1 + P2**，配置写回口径为**全量可写（不含敏感密钥）**。

### 1.1 配置写回口径（用户拍板「全量可写，不含敏感密钥」）

- **9 项非敏感可写**：live 立即热更新 6 项 `alert_webhook_url` / `rc_max_sec` / `rc_idle_sec` / `max_devices` / `backup_keep` / `hmac_enforce`；restart 重启生效 3 项 `backup_interval_hours` / `record_enabled` / `record_retention_days`。
- **敏感项黑洞**：`YUDUAN_HMAC_SECRET` / `YUDUAN_PEPPER` / `YUDUAN_SIGN_SEED` / `YUDUAN_CA_KEY` / `YUDUAN_TLS_KEY` / `YUDUAN_RECORD_KEY` / `YUDUAN_DB_DSN` / `YUDUAN_CLIENT_CA` / `YUDUAN_CLIENT_CERT` / `YUDUAN_CLIENT_KEY` / `YUDUAN_TLS_CAFILE` —— **绝不 GET 回显、绝不 POST 写**，只在 `sensitive_excluded` 清单提示「改 env/keystore 后重启」。
- 覆盖值原子落盘 `data/hub-config-overrides.json`（临时文件 + `os.Rename`，权限 0600），启动期 `loadConfigOverrides` + `mergeConfigOverrides` 只认已知 key、类型不符忽略。
- **RBAC**：`config:view` = admin + operator 可读，`config:write` = 仅 admin 可写，viewer 无配置读权限。拒绝统一为 **HTTP 200 + body `code=403`**（`writeErr` 契约，不是真实 HTTP 403）。

### 3.1 并发编辑实证与 P2-F 收口补强（本版新增）

23:36–23:38（主理人核验窗口内）工作树出现 6 个文件未提交改动（+146/−43），经 diff 判明为**有效补强而非污染**，且修掉一个真实协议漏洞：

1. **协议漏洞修复**：`rust/agent/src/main.rs` 的 `ch_ts` 原为 `.unwrap_or_else(now_secs)` —— 中枢挑战若缺 `ts`，副端会拿**本地时间**签名，违反「`ts` 唯一来源 = `auth_challenge.TS` 原值」，且中枢按自己下发的 ts 验签必然失败。改为 `Option<i64>`，缺失即跳过证明、回退旧三字段（旧副端兼容不变）。
2. 删除副端 `secure.rs::attestation_within_skew` 与 ±300s 窗口单测：副端不该做时间窗判定（规范串用原始 ts、判定却做归一，语义自相矛盾），责任交还中枢接线时旁路判定；`MAX_SKEW_SECS` 仍被 `verify_command` 使用，保留。
3. `devicekey.rs` 新增 `#[cfg(all(test, not(windows)))]` + `thread_local` CSPRNG 路径注入点（**生产二进制完全不编译**），补 2 单测：urandom 打不开 / 短文件 / 文件损坏时 `generate`/`load_or_create` 均 fail-closed，且旧三字段仍逐字节可构造；跨重启两次 seed 不重复（排除固定值 / 设备指纹派生）。
4. Go 注释与 `protocol.md §9.2` 同步 ts 口径；`attest_test.go` 明确黄金向量是**真跨语言闭环**（Go 验 Rust 常量签名），Go 标准库重算仅作 RFC 8032 兼容佐证。
5. 该快照质量门复跑：Go crypto 12 负例 PASS、`go build`/`go vet` RC=0、Rust **155 passed**。

## 6. 已知边界与技术债（诚实口径，不阻断本版）

| 项 | 状态 |
|---|---|
| 副端 attestation | **本期仅契约基座**：中枢 handler 验签叠加、白名单比对、审计联动、灰度开关**均未接线**；`require_attest` 默认不下发，副端默认产物与旧副端逐字节一致。协议 §9.2 与部署 README 已写明，**不构成已启用门禁** |
| 审计库外锚 | 只能靠人工 / 带外比对发现整库回滚，**本版不提供自动告警**；攻击者若同时删除锚文件仍需异地备份或只读介质。锚密钥三级优先：独立 `YUDUAN_AUDIT_ANCHOR_KEY` > 回退 HMAC_SECRET（标注 `key_source=hmac-secret-fallback`，能读 secret 者可自伪造）> 两者皆空则不锚定、不写文件、**绝不误报链损坏** |
| 会话安全 | 默认关闭（`YUDUAN_SESSION_ENFORCE`），`YUDUAN_SESSION_LEGACY_ALLOW` 宽限；令牌格式零改、sid = SHA-256(token)；备份导出排除 `yuduan_sessions` + 恢复跳过其 INSERT，**不改共用 `listTables()`**（否则 RestoreSQL 的 TRUNCATE 会漏掉会话表） |
| ACME 自动续期 | 需同时 `YUDUAN_NET_MODE=public` + `YUDUAN_ACME_AUTORENEW=1`；失败指数退避、不 `log.Fatal`、不降级明文 |
