# 御端 v0.4.33 · §9.2 设备证明「部署可达性 + 可观测」收口 — 测试与发布核验文档

> v0.4.33 范围：**修复 v0.4.32 Windows 服务器测试报告 #1/#2**——§9.2 强制证明逻辑本身正确，但部署器 `register-task.ps1` 未暴露 `YUDUAN_ATTEST_REQUIRE` / `YUDUAN_ATTEST_TRUSTED_MEASUREMENTS`，开关无法经支持的部署路径进入 hub 运行时，致「REQUIRE=1 不拒绝 + attested 不置位」。本版：① 安装器暴露 `-AttestRequire` / `-AttestTrustedMeasurements` 并幂等写入 `hub.env`；② 配置 API（`GET /api/v1/config` 的 `info.attest_require` / `info.attest_whitelist_count`）与启动日志回显证明开关状态，便于测试/运维确认开关已落地；③ 版本串 bump `0.4.33`。
> 前序：`output/v0.4.32-测试文档.md`。

### 1.1 根因（v0.4.32 测试报告 #1/#2）

- 现象：`YUDUAN_ATTEST_REQUIRE=1` 下 `attested` 仍为 `false`、白名单 miss 未拒绝。
- 核对（逐行）：`hub.go` 挑战 `RequireAttest: h.attestRequire`(737)、握手门(858-882)、注册公钥一致(907-915)、落库(960-967) 逻辑闭合；`main.rs`(1607-1644) 仅在 `require_attest` 为真时产出证明三字段；`proto.go` 字段对齐。
- **唯一共因**：运行时 `attestRequire` 恒为假——`register-task.ps1` 的 13 个参数从未暴露 attestation 开关，`YUDUAN_ATTEST_REQUIRE` 无法经受支持部署路径注入 hub 运行时（手工改 `hub.env` 才生效，但部署脚本「先清后写」会回退）。

### 1.2 修复（commit `6612763`）

- **部署器可达性**：`register-task.ps1` 新增 `-AttestRequire`(switch) / `-AttestTrustedMeasurements`(string) 参数；显式传参时幂等 `Set-HubEnvLine` 写 `hub.env`（与 `-Public` 行为一致：仅显式传参才写该键，未指定保持既有）；`-AttestTrustedMeasurements` 做 64hex 格式校验。
- **可观测**：`config.go` 新增 `Hub.AttestRequire()` / `AttestTrustedMeasurements()` 访问器；`GET /api/v1/config` 的 `info` 段回显 `attest_require`(bool) 与 `attest_whitelist_count`(int)；`main.go` 启动日志显式打印「设备证明：强制校验已启用/未启用 + 白名单条目数」。
- **版本串**：`main/package.json` + `main/src-tauri/tauri.conf.json` bump `0.4.33`。

## 6. 已知边界与技术债（诚实口径）

| 项 | 状态 |
|---|---|
| 设备证明启用条件 | 全网强制 `YUDUAN_ATTEST_REQUIRE=1` 要求全网副端 ≥ v0.4.31（含 §9.2 契约基座）；混网旧副端在强制模式下会被拒绝，须先完成全网副端升级再开灰度 |

| 安装器语义 | 仅显式 `-AttestRequire` 才写 `YUDUAN_ATTEST_REQUIRE=1`；未指定保持 `hub.env` 既有值（不主动置 0），与 `-Public` 行为一致；手工改 `hub.env` 后仍可被后续无参重跑保留 |
