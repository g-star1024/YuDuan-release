### 任务① 落点（发布仓 workflow `release-build.yml`）

| 环节 | 改动 |
|---|---|
| build 主端 | `npx tauri build --no-bundle` → `--bundles nsis`。裸 exe 仍在 `target/release/yuduan-main.exe`（bundling 只追加安装器、不移除裸二进制）——既有「免安装直接运行」形态不变 |
| 签名 | signtool 门控段内追加 `bundle/nsis/*-setup.exe` 签名（无证书时整段跳过，与既有门控一致） |
| 产物上传 | upload-artifact `windows-client` 增 `main/src-tauri/target/release/bundle/nsis/*-setup.exe` |
| Release | publish 改名 `YuDuan-main_${TAG}_windows_setup.exe` 上架（缺席仅 `::warning::` 降级 15 资产，不阻塞其余产物）；Release 说明补静默用法 |
| 主端配置 | `tauri.conf.json` `bundle.windows.nsis.languages = [SimpChinese, English]`（安装器界面中英文） |

**静默分发用法（V7 回收口径）**：
- 静默安装：`YuDuan-main_v0.4.43_windows_setup.exe /S`（NSIS 标准 `/S`）；
- 自定义目录：`/D=x:\dir`（须置于参数末尾、不带引号）；
- 静默安装完成后，运行 `%LOCALAPPDATA%\YuDuan\yuduan-main.exe`（currentUser 模式）即可回收 V7：验 `%APPDATA%\YuDuan\logs\main.log` 产出运行期日志。

### 任务② 落点（build-macos 门控步，替换原 ad-hoc 步）

配置以下 Secrets 后自动启用（门控在脚本体内判 env，**不碰 `if:`+secrets 铁律**）：
- `APPLE_CERTIFICATE`（Developer ID Application .p12 base64）、`APPLE_CERTIFICATE_PASSWORD`
- `APPLE_ID` / `APPLE_PASSWORD`（App 专用密码）/ `APPLE_TEAM_ID`

启用后流程：临时 keychain 导入 p12 → 找 `Developer ID Application` 身份 → 双架构 .app `codesign --options runtime` + dmg 签名 → `notarytool store-credentials` + `submit --wait` → `stapler staple` → 清理。产出 dmg **免右键双开**（不再「已损坏」误报，也不需右键打开）。未配置 Secrets：回退 ad-hoc，行为与 v0.4.42 及以前完全一致。

## 2. 审计/裁决要点

1. **「15/15」→「16/16」**：新增第 16 个资产 `YuDuan-main_v0.4.43_windows_setup.exe`。publish 对 setup 缺席走 `::warning::` 降级（与 mac/arm64 尽力而为产物同款模式），不会因单项缺席阻塞其余 15 件。
2. **NSIS 与 N1 中文路径问题无关**：N1 是部署器解压 PG zip 的 `cmd` 代码页错配；NSIS 安装器自身为 Unicode 安装器，不经过 `cmd /c tar`。
3. **取消 skip 铁律不新增风险**：未改 publish 的 `needs` 结构（仍 4 关键 job）；mac 仍在 publish 内轮询终态。
4. **裸 exe 保留**：`--bundles nsis` 不移除裸二进制，免安装形态、副端自安装 exe、既有部署文档全部不受影响。
