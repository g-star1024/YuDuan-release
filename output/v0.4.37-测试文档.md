- 中枢可达（HTTP 200，隧道 RTT≈1.5–1.7s）；登录 `code:0` 正常。

## 3. 修复实现

新增 `hub_host_is_lan(base: &str) -> bool`（`lib.rs`）：剥离 `ws/wss/http/https` 前缀取 host；
`localhost/127.x/10.x/172.16-31.x/192.168.x/IPv6` → 内网；非 IP 主机名/空 → 远端（保守走中继）。

`rc_start` 默认 transport：
```rust
let default_transport = if hub_host_is_lan(&base) { "auto" } else { "relay" };
let opts = SessionOpts {
    transport: transport.unwrap_or_else(|| default_transport.into()),
    ...
};
```

- 主端与中枢同局域网（host 内网）→ `"auto"`（P2P 优先，最低延迟）。
- 主端从公网/隧道连中枢（host 远端）→ `"relay"`（零等待，跨网直接可达）。
- 语义：远端连中枢时，所有 RC 会话默认走中继（选到内网副端也经中枢 WS 跨网可达），彻底消除 5s 空等+连不上；同局域网维持 P2P。

**已知边界（非本次范围）**：主端在 LAN 而选到"远端注册"的副端时，仍会先试 P2P 再回落——按副端 host 精细化寻址为后续增强。
