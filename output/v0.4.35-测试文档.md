### 1.1 根因与修复映射

| 编号 | 现象（实测矩阵） | 根因 | 修复 |
|---|---|---|---|
| #A（关键） | 干净机（无任何 PG）纯一键 0/8 成功：便携 PG 下载 299.9MB→initdb→yuduan-pg 就绪后立刻中止「未配置 PostgreSQL 且未能自动就绪」 | `register-task.ps1` 的 `Invoke-Psql` 只返回**命令退出码**，`$script:PgResult` 虽捕获查询输出但**无人使用**；`Grant-YuduanRole` 用 `if (Invoke-Psql "SELECT 1 FROM pg_roles WHERE rolname='yuduan';") { return $null }` 把「0 行+退出码 0」误判为「角色已存在」→ 直接放弃建号；库存在性判断 `-not (Invoke-Psql ...)` 在空库上恒为 false → `CREATE DATABASE` 永不被执行 | 存在性判断改看**结果集**：`if ((Invoke-Psql ...) -and $script:PgResult) { return $null }`（角色）；`if ((Invoke-Psql ...) -and -not $script:PgResult) { CREATE DATABASE }`（库）。空结果集（含查询失败）一律尝试建号/建库 |
| #4（确认缺陷） | `port8080-occupied` 用例：中枢进程已起（fb_hub_procs=1），但自检三项全 HTTP 000；脚本仍提示 `http://localhost:8080` 并退出码 0 → deploy.bat 误判成功 | ① 自检探针硬编码 `127.0.0.1:8080`，而中枢在 8080 被占用时回退 8081/8082/8083/18080（`main.go:420 listenPlainOrFallback`），自检探错端口；② `register-task.ps1` 打印「❌ 自检存在失败项」后**不设置非零退出码**，deploy.bat 据此返回 0 | ① 自检前从 `hub.log` 本轮新增内容解析实际绑定端口（`明文中枢监听 :PORT` 优先，`自动改用 :PORT` 次之），`$base` 改用实际端口；② 自检失败（`$allPass=$false`）显式 `exit 1`，deploy.bat 经 `if %errorlevel% neq 0` 正确判失败；③ 成功时把实际端口落盘 `data\hub-port.txt`，deploy.bat 末尾读取并提示真实地址 |

> 实测矩阵其余整改建议（#1 便携 PG 参数化 PG_PORT / #2 副端服务停止控件 / #5 结构化原因码 / #6 机器可读结论）在本版**未实现**，作为后续建议（§7），理由见 §6/§7。

## 4. 测试验证矩阵

## 6. 已知边界与技术债（诚实口径）

| 项 | 状态 |
|---|---|
| #A 修复后 PG 自动就绪全链 | 干净机首次真正走通；但**便携 PG 仍硬编码 5432**（`$PG_PORT=5432`）——若 5432 被**非 PG** 监听占用（实测矩阵的 `port5432-occupied` 用例），脚本走「端口占用但非标准安装→跳过」分支并失败（见 §7 #1） |
| #4 端口回退 | 中枢 8080 被占→回退 8081/8082/8083/18080；自检与提示现已用实际端口。但**显式指定 `YUDUAN_HUB_ADDR` 时中枢失败即退出（不回退）**，部署脚本不感知该显式端口——属更小众场景，本期未特别处理 |
| 中枢重启影响（同 v0.4.34 N5） | 重启重放强制改密，`admin` 口令重启后再次被要求改密；运维脚本须每次重启后重做改密 |
| 副端可复现构建（同 v0.4.34 N4） | 以 PE `FileVersion` / 包名版本为准，勿仅按哈希判版本 |
| 遗留文档（#94） | `御端-v0.2.6-全量功能操作指引.md` 仍不可恢复；根目录 `御端-v0.2.6-全面复盘报告.md` 按用户指示保持未跟踪、不入库保全 |

## 7. 后续建议（实测矩阵整改清单未实现项）

1. **#1 便携 PG 参数化 PG_PORT + 独立数据目录**：当前便携 PG 固定 5432，无法规避 `port5432-occupied` 类失败。建议在 `register-task.ps1` 新增 `-PgPort` 参数（默认 5432）并贯穿 `initdb`/服务注册/DSN；#A 修复已为此扫清「建号建库」障碍，此项可在其上叠加。
2. **#2 副端服务接受停止控件 / 绕开标记删除**：本期矩阵只测中枢一键，副端侧维持 v0.4.34 结论（就地升级不删服务、零 1072）。
3. **#5 降级项升级为阻断/原因码**：当前失败仅中文 WARN 段落，无结构化原因码（如 `PG_ROLE_BOOTSTRAP_BUG` / `PORT_5432_FOREIGN`）；外部判定只能靠进程+登录探测。建议 hub/脚本产出结构化原因码，便于自动化分流。
4. **#6 一键末尾输出机器可读结论**：建议 deploy 末尾同时写一个 `deploy-result.json`（成功/失败 + 实际端口 + 原因码），供外部编排消费，而非仅靠退出码。

> 以上四项均为**增强型整改**，非本版已确认缺陷；是否与用户排期纳入下个版本待定。
