# 御端 v0.4.26 · P1 公网可达最小闭环 — 测试与发布核验文档

> 本文档记录 v0.4.26（P1 里程碑）的代码收口、质量门、真机验证计划与发布核验结论。
> 配套宪法修订见 `御端-项目开发铁律.md` v1.2 与 `dev/proto/protocol.md` §1（Gate G-2026-11-06-02）。

## 1. 里程碑背景

- **Gate G-2026-11-06-02**：铁律 1 v1.2 覆盖 v1.1 纯手动自建口径——产品须内置「公网远控能力包」
  （公网端点 / 内置中继 / NAT 穿透 / 自绑域名 / 一键部署向导 / LAN·公网 开关），产品自身仍不运营、
  不托管任何公网服务；证书支持 ACME/Let's Encrypt 自动签发与自传证书/私有 CA 双轨；`Ver` 保持 1。
- **分期**：P1 = 公网可达最小闭环（本次）；P2 = 内置中继组件；P3 = NAT 穿透 + 最小白化向导。
- **两决策（用户拍板）**：① ACME 自研 Go HTTP-01 客户端（零第三方依赖）；② 仅 `public` 形态才广播公网
  （默认 `lan` 保持零配置、仅内网、不广播公网地址、不开登录防爆破）。

## 4. 真机 / 手册验证计划

> P1 的「公网可达」端到端闭环依赖客户公网环境（公网 IP + 域名 DNS + 开放 80/443），
> 无法在局域网 CI 内自动跑通。以下为交付后的必做真机验收项（建议用户在自家环境按序核验）：

1. **LAN 默认零回归**：不加 `-Public`，部署后中枢仅 `:8080`+`:8443` 自签 + UDP `:18242`，主端/副端 LAN 自动发现上线、远控正常——确认 v0.4.25 行为一字未变。
2. **ACME 真机签发**（staging 先测）：`yuduan-acme issue --domain <你的域名> --email <邮箱> --staging` → 确认 `certs/acme.fullchain.pem`/`acme.key`/`acme.pin` 产出；正式签发去掉 `--staging`。
3. **公网形态启动**：`YUDUAN_NET_MODE=public` + `YUDUAN_TLS_CERT=certs/acme.fullchain.pem` + `YUDUAN_TLS_KEY=certs/acme.key` 启动中枢，确认：① 不报「必须显式配置 TLS 证书」fatal；② 日志打印「网络形态：公网」；③ `YUDUAN_PUBLIC_ADDR` 推导为 `https://域名:8443`；④ 登录防爆破默认开。
4. **主端公网连接**：Settings 切「公网」+ 填域名 → 主端 `base` 推导 `https://域名:8443`，登录成功；切回 LAN 后不被公网地址覆盖。
5. **副端公网连接**：副端设 `YUDUAN_HUB=wss://域名:8443/ws/agent`（ACME 证书系统根已信任则无需额外锚），注册上线、远控画面可达。
6. **一键闭环**：`register-task.ps1 -Public -Domain <域名> -Email <邮箱> -CertMode acme`（或 `install.sh --public ...`）跑通，env 正确写入、防火墙放行、副端提示打印。

## 5. 风险与遗留

- **ACME 仅离线单测**：`TestIssueLiveStaging` 默认跳过（需公网 :80 + 域名 DNS），真机签发由用户在 §4.2/4.6 核验。
- **ACME 仅 HTTP-01**：不支持 DNS-01（通配/无 80 端口场景不适用），符合铁律「需公网 IP + 开放 80/443」前提。
- **中继/穿透未做**：P2/P3 里程碑，P1 仅到「公网端点 + 域名 + 证书 + 开关」，直连失败无兜底。
- **主端信任锚**：ACME（公网可信 CA）下主端无需额外锚；self/私有 CA 模式仍需 `YUDUAN_TLS_CAFILE`/`PIN`，已在向导与 README §G 注明。
