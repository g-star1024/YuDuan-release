### 3.1 独立行为回归（主理人二次实跑，非复用 worker 自验）

最小 env：`YUDUAN_HMAC_SECRET=smoke-only-not-a-real-secret`；每组独立 `mktemp` 干净目录，`subprocess` 10s 超时。

| # | 场景 | 断言 | 结果 |
|---|---|---|---|
| A | `NET_MODE=public`，无证书 | 第一行即 fatal「缺少显式 TLS 配置」，`exit=1` | ✅ |
| A2 | 同 A，但目录预置诱饵 `certs/chain.pem` + `certs/acme.fullchain.pem` + key | **仍 fatal**，且日志不出现「自动采用探测到的证书」 | ✅ **F-10 决定性证据** |
| A3 | A2 输出中不得出现自动采用 | 自动探测分支确已删除 | ✅ |
| B | `NET_MODE=public` + 显式 `TLS_CERT/TLS_KEY`（路径可不存在） | 无形态门 fatal，出现「前置校验：公网形态未设 …」+「网络形态：公网」 | ✅ |
| C | 默认 LAN（不设 NET_MODE） | 无形态门 fatal，正常打印「网络形态：局域网」并进入后续启动流程 | ✅ **LAN 零回归** |

> F-05 旁证：A/A2 的 fatal 是进程**第一行输出**，早于 `SeedDefaultAdmin`（argon2 64MiB×3）；
> C 的输出中「内置 admin 首次登录需强制改密」排在形态日志之后，证明前置校验确在 argon2 之前完成。
> 注：首轮 smoke 未补 `YUDUAN_HMAC_SECRET`，B/C 在更前面的 HMAC 致命处退出导致 2 条断言假阴性；

## 4. 真机复测计划（Windows）

1. **F-10 根修复测**：LAN 一键部署目录（含 `certs/chain.pem`）手工把 `NET_MODE=public` 写入 `hub.env`、不配证书 → 必须 `exit=1` 明确 fatal，日志不得出现「自动采用探测到的证书」；补上显式证书 env 后再启动应正常。
2. **F-05 复测**：低内存条件下 public 无证书，应在 argon2 初始化之前给出 fatal（不再 OOM 堆栈）。
3. **F-04 复测**：public 形态回环 `127.0.0.1` 连续 6 次错误密码 → 第 6 次应 `code=4029` 锁定；非回环行为不变；就绪探针与自检③仍正常（HTTP 200）。
4. **F-03 复测**：`GET /api/v1/devices` 中文 publisher 应正常显示，JSON 中 U+FFFD 数量归零。
5. **F-01/F-02 复测**：随包 README 应含 §G、新口径与两条警告；`register-task.ps1 -Public ... -Staging` / `install.sh --public ... --staging` 应把 `--staging` 透传给 `yuduan-acme`（本地 mock ACME 可验）。
6. **F-06 复测**：ACME 请求链各阶段有进度日志；网络不通时能看出卡在哪一步。
7. **LAN 零回归**：全新安装（默认端口 8080/8443/UDP 18242）→ 自检 3/3 → 副端零配置广播发现 + claim 上线 → 登录/设备/统计/审计接口正常。

> 仍未覆盖（需客户公网环境）：真实公网 ACME 签发、主端 Settings 切公网 + 域名登录、副端公网 wss 注册、一键 `-Public` 全流程、PostgreSQL 持久化（测试机 5432 被 MedCRM 占用）。

## 5. 技术债与已知限制（本版登记，不修）

- **本机反代不支持**：反代下 `loginGuardKey` 只取 RemoteAddr → 单键跨来源账号锁定 DoS；`hub.go:519/527/532` 审计来源 IP 全塌成 127.0.0.1。若后续要支持，前置项 = 可信代理白名单 + 仅对该白名单采信 XFF（**A/B/C 任一豁免移除方案的共同前置条件**），单列一批。
- **F-07**：UDP 发现端口 18242 写死（`discover.go:24`），三端 + 脚本 + 协议文档联动，多实例并存需整体改造。
- **F-09**：hub/agent/acme/ca 的 Windows PE `ProductVersion`/`FileVersion` 为空，需 goversioninfo/rcedit CI 资源步骤（Rust 侧 rustc 直编不能用 build.rs）。
- **F-08**：W5A 合规采集 20s 指令等待偶发超时，每轮扫描自愈，真机服务化复测留痕。
- **ACME 仅 HTTP-01**：不支持 DNS-01；P2 内置中继 / P3 NAT 穿透未做。
- **PS1 语法无法本机实跑**：本机 macOS 无 `pwsh`，`register-task.ps1` / `deploy.bat` 的 `-Staging` 透传与 `set /p` 括号块解析仅经逐行静态审查，需在中文 Windows 真机补一次 `-Public -CertMode acme -Staging` 端到端。
- **macOS 无一键 `-Public` 入口（本版新登记，未修，待拍板）**：三平台 hub 包均随附 `yuduan-acme` 与 `prepare-public-cert.sh`，但 macOS 包只有 `install-macos.sh`（85 行，实测不含 `--public` / `acme` / `staging` / `YUDUAN_NET_MODE`），公网形态须按 §C 手工配置；随包 README §G L348「三端脚本一致」易被误读为三端都有一键入口，实际下方只列 Windows / Linux 两个入口。建议下一版统一措辞为「三端默认 LAN 行为一致」或补齐 macOS `-Public`。**本次不重出包**：该项不在 F-01~F-10 已批准范围内，改随包文本需删推 tag + 重跑 CI + 重新核证 15 产物，成本与风险由用户裁定。
- **服务器整包未逐包下载**：`YuDuan-hub-server-db_v0.4.27_windows_amd64.zip`（322,811,224 B）体积过大，未下载逐件核验；其与 Windows hub 包同一次 `build-hub` job 产出，随包文档同源。
