## 4. 实机测试指引（Windows 服务器，第九轮验收）

### 4.1 自检③（修复 1 的直接验证）
- `cleanup.ps1` → `register-task.ps1 -ResetConfig`。
- **预期**：`[PASS] ③ 登录接口 POST /api/v1/login -> 200 code=0`（首次改密部署时 admin/admin123 应当直接 code=0，不再出现"七轮 WARN"）。
- 若密码已改（非默认）：出现 `[WARN] … 401=鉴权正常` 属预期语义（可登录性已被 hub 回环探针证明）。
- **反面验证（可选）**：临时改坏 body 文件内容再跑，FAIL 分支应打印「实际发出 body」，证明诊断输出生效。

### 4.2 远控采集通知（修复 2）
- 正常远控：整个会话**不应**再出现任何"采集不可用"通知（v0.4.15 在部分环境首帧前偶发 1 次失败重试）。
- 若环境确有短暂失败：先看到「暂时不可用…正在重试」，随后**必须**出现「屏幕采集已恢复（此前短暂中断 N 次）」，且画面持续出帧——状态条不再停留旧文案。
- 锁屏/安全桌面场景：失败通知应持续且明确"安全桌面/锁屏"，不与正常出帧行为矛盾。

### 4.3 审批接口 400（修复 4）
```bash
# 非法写法（此前被静默判拒）→ 预期 HTTP 400 + code=2009
curl -X POST "$BASE/api/v1/rc/approvals/apr-1" -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" -d '{"decision":"approved"}'
curl -X POST "$BASE/api/v1/rc/approvals/apr-1" -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" -d '{"approved":true}'
# 合法写法 → 行为不变（2004=工单不存在 / 正常审批流）
curl -X POST "$BASE/api/v1/rc/approvals/apr-1" -H "Authorization: Bearer $TOKEN" \
     -H "Content-Type: application/json" -d '{"approve":true}'
```
- 主端 UI 审批按钮（走 `{approve, reason}`）回归一遍确认不受影响。

### 4.4 W2-1 / W5-6 冒烟（补测项 3，纯接口级）
- **W2-1 拉文件**：副端服务配置环境变量 `YUDUAN_RC_PULL_ROOT=<允许目录>` 后重启副端 → 主端 UI 文件同步页发起拉取 → 验证文件落盘与审计事件。
- **W5-6 模板详情**：先造数据再下钻——`POST /api/v1/strategy/templates` 创建模板（e2e_wave5c.py 有现成请求体），随后 `GET /api/v1/strategy/templates/{id}` 验证创建者/目标组/规则/绑定字段非空。
