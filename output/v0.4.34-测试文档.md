# 御端 v0.4.34 · v0.4.33 Windows 测试报告问题修复 — 测试与发布核验文档

> v0.4.34 范围：**修复 v0.4.33 Windows 服务器测试报告发现的 7 项问题中的可落地项**，发布 v0.4.34：
> - **N1（高）**：部署器 `register-task.ps1` 仅能开不能关、白名单只能覆盖不能清——新增 `-AttestState on|off` 与 `-ClearAttestWhitelist`，使灰度开启后可经部署器回退/清空，满足「部署器是唯一受支持配置路径」口径。
> - **N3（低）**：中枢两条拒绝日志口径重排——区分「未提供凭据（顺序无关，递延）」与「凭据已提供但校验失败（attest）」，避免运维误读为凭据缺失。
> - **N2（中）**：① 中枢 attest 失败三类拒绝除日志/审计外再触发 `attest_failed` 类型告警（`addAlert` 按 Type+DeviceID 去重，握手期 DeviceID 为空 → 同类拒绝自动聚合为单条未读告警）；② 副端注册被拒后重连做指数退避（5→10→20→40s，封顶 60s），缓解拒绝风暴。
> - **N6（中）**：副端安装器 `wait_enter` 超时后无条件 `std::process::exit(0)`，文案只打一次，解决「承诺 15 秒自动退出却不退出」导致无人值守/远程部署窗口常驻挂会话。
> - **N7（中）**：副端卸载 `DeleteService` 后「标记删除」释放等待上限做成可调（`YUDUAN_SVC_DEL_WAIT_SECS`，默认 60s，上限 600s），超时明确提示「重跑安装器即可恢复」。
> - **N4/N5（低）**：作为文档说明项随操作手册 + Release 说明更新（可复现构建哈希提示 / 重启强制改密影响标注），不改动代码。
> 前序：`output/v0.4.33-测试文档.md`。

### 1.1 根因与修复映射

| 编号 | 现象（v0.4.33 测试报告） | 根因 | 修复 |
|---|---|---|---|
| N1 | 证明开关只能开不能关、白名单只能覆盖不能清；一旦灰度开启只能进生产机手工改 `hub.env`，与「部署器是唯一受支持路径」自相矛盾 | `register-task.ps1` 只有 `-AttestRequire`(写 1)，无 off/清除语义 | 新增 `-AttestState on\|off`（写 0）+ `-ClearAttestWhitelist`（删行）；解析优先级 `-AttestRequire` > `on` > `off` > 留空 |
| N3 | 被拒时先打「拒绝未认证注册（缺少 §9.1 凭据握手）」再打「设备证明校验失败」，副端其实已具备凭据能力；放行态也会看到前一条 | 未握手 register 一律打「拒绝」日志，但实为顺序无关的正常递延 | 重排口径：前一条改为「收到注册请求但尚未完成 §9.1 凭据握手（顺序无关，连接保持）」；attest 分支保留明确「设备证明校验失败」 |
| N2 | S3 窗口 10+ 次尝试恒定 5~9s，日志刷满；拒绝仅日志不告警（alerts unread 未体现） | 副端重连恒定 3~9s 抖动、未随拒绝递增；中枢 attest 失败只 audit 不 addAlert | ① 中枢 `addAlert(AlertAttestFailed)`，按 Type+DeviceID 去重聚合；② 副端 `AUTH_REJECT_STREAK>0` 时叠加指数退避 |
| N6 | 安装器承诺「15 秒后自动退出」但窗口常驻不关；上一行又写「本窗口可以直接关闭」，两种口径叠加 | `wait_enter_or_timeout` 超时返回后未退出，spawn 的 stdin 读取线程阻塞进程 | 超时后无条件 `std::process::exit(0)`；统一文案「窗口 15 秒后自动关闭，也可按回车立即关闭」 |
| N7 | 卸载阶段等「标记删除」释放耗满 60s 上限，一次重装 77s+17s | `DeleteService` 后轮询 SCM 释放窗口固定 60s、不可调，超时无结论 | 等待上限做成可调 `YUDUAN_SVC_DEL_WAIT_SECS`（默认 60s，上限 600s）；超时打印「重跑安装器即可恢复」 |

## 6. 已知边界与技术债（诚实口径）

| 项 | 状态 |
|---|---|
| 设备证明启用条件 | 全网强制 `YUDUAN_ATTEST_REQUIRE=1` 要求全网副端 ≥ v0.4.31；混网旧副端在强制模式下会被拒绝，须先完成全网副端升级再开灰度 |
| 度量白名单 | `YUDUAN_ATTEST_TRUSTED_MEASUREMENTS` 逗号分隔 SHA-256 hex；留空 = 仅验签 + 公钥一致；启用白名单须各平台度量值已采集对齐，否则全部拒绝 |
| N2 副端退避上限 | 拒绝指数退避封顶 60s，配合连续 3 轮清密钥自愈；拒绝风暴期间副端侧不再恒定 5~9s 刷屏 |
| N6 交互态 | `--quiet`/非交互/管道场景本就直接返回；仅交互控制台场景走 15s 倒计时 + 超时 exit；`exit(0)` 跳过析构但安装/升级工作已完成，安全 |
| N7 实战建议 | 安装目录不变的升级走「就地升级」（停服务→替换→启动，不删服务、零 1072）；N7 可调窗口仅作用于显式卸载 / 安装目录变更的全量路径 |
| N4 可复现构建 | 副端源码零改动也可能换哈希；以 PE `FileVersion` / 包名版本为准，本发布附版本哈希清单 |
| N5 重启影响 | 重启重放强制改密，运维脚本须每次重启后重做改密 |
| 遗留文档（#94） | `御端-v0.2.6-全量功能操作指引.md` 仍不可恢复；根目录 `御端-v0.2.6-全面复盘报告.md` 按用户指示保持未跟踪、不入库保全 |

## 7. 后续建议

1. **部署后实机核验 §4 的 ⏳ 项**：Windows 跑 `register-task.ps1 -AttestState off` / `-ClearAttestWhitelist` 确认开关可关可清；强制模式下验证 `attest_failed` 告警聚合与副端退避；无人值守 `-setup` 验证窗口自动退出。
2. **N2 全量告警子系统**：本版仅把 attest 失败接入已有 `addAlert` 去重；如需「同类拒绝计数/阈值升级」等高级聚合，排期独立 issue。
3. **跨网轮阻塞项（维持）**：副端远端中枢指定（YUDUAN_HUB 注入）、服务可停止、落盘日志仍是 §9.2 灰度的真实前置阻塞，建议与「全网副端 ≥ v0.4.31 才开强制」边界一起排期。
